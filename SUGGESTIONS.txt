EVERYDAY USE
------------

[x] DONE 0.26 The shopping list counts amounts. (v3.3.3)
    "Make the shopping list" adds up the week's meals that aren't cooked yet per ingredient, compares that with the
    stock in the stored item's unit (grams against kilos, millilitres against litres) and lists only what is short:
    "Flour 650 g · Pancakes, Bread". Under a kilo or a litre it says grams or millilitres. Where the amounts can't be
    compared ("1 bunch" against "200 g", a teaspoon against grams) the item counts as enough, as before.
    Found on the way: stock matching found short names from other languages inside longer ones (Dutch "ei" in
    Portuguese "leite" and "queijo", Turkish "un" in Romanian "pătrunjel"), so milk, cheese and salt counted as
    "Eggs" in stock and parsley as "Flour". A name now only counts inside another when it is longer than three letters.

0.27 Thaw reminders the evening before.
    Frozen food has a "Frozen on" date and the week has planned meals, but nothing connects them. When tomorrow's
    meal needs something that is only in the freezer, show "Move the chicken to the fridge" in Use soon the evening
    before, and as a reminder notification where those already work (phone apps, HTTPS browsers). It's the one step
    that most often ruins a planned meal.

0.28 "What can I make with it?" from Use soon.
    Use soon lists what is about to go off, and the week planner already puts recipes that use it first, but only
    when you're planning. A button on each Use soon item could open the Recipes page searched for that ingredient,
    own recipes first, then Recipe ideas (TheMealDB) for the same ingredient, so the answer is one tap from the
    warning.

0.29 A quick stocktake, one place at a time.
    An inventory app is only as good as its counts, and they drift: things get used without anyone tapping −. A
    "Check the fridge" mode would show one location's items as big rows with "Still there", "Less" (edit the
    amount) and "Gone" (with the used up / thrown away question), and remember when each place was last checked
    ("Freezer: checked 5 weeks ago"). Five minutes once a week keeps everything else (Use soon, the shopping list,
    "in stock") right.

0.30 Learn shelf life from what gets thrown away.
    From 0.10. state.log already knows when something was thrown away and how long it had been in the kitchen. When
    the same thing keeps being thrown away before its estimate (bread binned after 4 days, estimate 7), suggest the
    shorter time for that item, shown as "your kitchen: 4 days" and used for new items once accepted. Only suggest
    after a few times, and never lengthen an estimate on its own: that's the food-safety side.


PHONE AND DESKTOP APPS
----------------------

0.31 Android home-screen widget.
    The quickest look at the kitchen without opening the app: "Use soon: milk (tomorrow), spinach" and "Shopping:
    7 items", tapping through to the right page. The app already hands Android the use-soon list for the daily
    reminders (setReminders), so the widget can read the same list, and it works with the app closed.

0.32 Print from the Android app.
    From 0.14. The browser and the desktop app print recipes and the shopping list; the phone apps' web views can't.
    Android's PrintManager can print a WebView, so one bridge call (print) would bring the same print styles to the
    phone, including printing to PDF to send to someone. iOS has the same through UIPrintInteractionController.

0.33 Photos for recipes imported in the phone apps.
    From 0.13. The server version downloads an imported recipe's photo and keeps a small copy inside the recipe; the
    phone apps keep only the web address, because their bridges fetch text. A bridge call that returns an image as
    a data URL would let the page shrink it the same way, so the photo also shows offline and in backups.

0.34 Share one recipe.
    Today a recipe only leaves the kitchen inside a whole backup, or by its original web link. "Share recipe" on the
    recipe page could send it as text (readable anywhere, and parseRecipeText already reads that text back in) plus
    a small .goodstock-recipe file that Import takes as it is, photo and steps included. Handy for sending a family
    recipe to someone with their own Goodstock.

0.35 Desktop: keep hosting with the window closed.
    On Android, hosting keeps running in the background (0.1). On the desktop, closing the window quits the app and
    the phones lose their home server. While hosting, closing the window could keep Goodstock in the system tray
    ("Goodstock is still sharing your kitchen", with Open and Quit), and optionally start with the computer.

0.36 GitHub-built APKs that update your own install, and update checks on Android.
    From 0.25. The APKs GitHub builds are signed with a different key than yours, so they can't update the app
    you installed. With the release key as a GitHub secret (only with your OK; it's never committed) every GitHub
    APK would install as an update, and the same daily update check as the desktop app could point to it.


SERVER VERSION
--------------

0.37 A small summary for Home Assistant and dashboards.
    A read-only /api/summary (use soon with dates, shopping list count, today's meals) that the household PIN's
    tokens can read. Home Assistant's REST sensor could then show "3 things to use soon" on a wall tablet or
    announce tonight's dinner, without anyone writing code for the app's full state.

0.38 Copy the server backups somewhere else.
    The daily backups (0.18) sit in /data/backups, on the same disk and volume as the kitchen itself, so a dead disk
    or a deleted volume takes both. An optional second mount (BACKUP_COPY_DIR, for example a NAS share) that gets a
    copy of each backup costs one line in Compose and covers that.


KEEPING IT HEALTHY (FOR WHOEVER WORKS ON THE CODE)
--------------------------------------------------

0.39 A quick check for code the kitchen tablet can't run.
    The Chromium 80 run (0.22) only catches what it opens. A static check in `npm test` that parses every app file
    as ES2020 (acorn) and looks for the methods Chrome 81 lacks (replaceAll, .at(), Object.hasOwn, structuredClone,
    CSS inset) would also catch code in rarely used paths, in a second instead of a minute.

0.40 Accessibility check in the tests.
    The app is meant for a kitchen tablet, wet hands and bigger text. Running axe-core on every page and the main
    dialogs (light, dark and large text) would catch missing labels, low contrast and buttons that are too small,
    and keep them from coming back.

[x] DONE 0.1 Keep "Host this kitchen" running on Android when the screen is off. (v3.0.4)
    HostService, a foreground service, runs while hosting. It shows a quiet "Sharing your kitchen" notification in the
    app's language, which opens the app when tapped, and holds a wake lock and a Wi-Fi lock. If Android stops the
    app, the service restarts and resumes the host with the same PIN and kitchen. Stopping hosting in Settings ends
    the service too. There's no Stop button on the notification: stopping from there would leave the page thinking it
    still hosts. Some makers (Samsung, Xiaomi…) still close background apps; android/README says to set battery use to
    Unrestricted.
    STILL TO CHECK on a real phone: the other devices stay in step with the host's screen off for an hour.

[x] DONE 0.2 Try the two new ways of sharing (v3.0.2) on real devices. (v3.0.4, the part that can be done in code)
    Conflict copies: Syncthing, Dropbox, iCloud ("… 2.json") and Google Drive copies were already ignored, because
    their names don't match. OneDrive's "goodstock-sync-<id>-PCNAME.json" did match: it was read as a new device, and
    an old copy brought back items deleted since. Now a file is only read when the device named inside it matches
    its file name. The shared-folder test checks four kinds of conflict copy; without the fix it fails. iCloud
    placeholders (".name.icloud") were already downloaded first. When the host goes away, the others already show
    "Working offline · Home server not reachable · will try again" and keep their changes.
    STILL FOR YOU: a week of real use with your sync app, to see how long files take to arrive.

[x] DONE 0.3 Re-schedule the daily reminders after an Android restart. (v3.0.4)
    BootReceiver schedules the use-soon reminders and running timers again from the last lists the app gave, after a
    restart and after an app update, without opening Goodstock.

0.4 Run the iPhone app on a real iPhone.
    [ ] ON HOLD (2026-10-18): waiting until a Mac that can build the app is available.
    From 1.1, still open. The workflow now builds an unsigned .ipa for sideloading from Windows (v2.1.69). Check by
    hand: a timer rings with the phone locked, backup and restore through Files, barcode scanning, and the new

0.5 A real person reads the languages your household uses.
    [ ] ON HOLD (2026-10-18): waiting until people are found to test the languages.

[x] DONE 0.6 Search in the inventory and in recipes. (v3.2.0)

[x] DONE 0.7 Staples: "always keep at least …". (v3.2.0)

    shopping list once, with a "restock" tag. If you take it off the list, it isn't added again until it has been
    back above the minimum. Removing a staple also lists it, and putting it away keeps it a staple.

[x] DONE 0.8 "Opened" and "frozen on" dates. (v3.2.0)
    "Opened today" in the edit dialog shortens the date to how long the item keeps once open (milk 4 days, canned

    holds while closed. Freezer items have a "Frozen on" date (today for new ones), and the estimate counts from it.
    The row shows "opened …" or "frozen …".

[x] DONE 0.9 Leftovers after cooking. (v3.2.0)

[x] DONE 0.11 Barcodes in "Put away", and scan to use up. (v3.2.1)

SERVER VERSION
--------------

[x] DONE 0.17 Easy HTTPS (biggest win for the server version). (v3.2.7)
    An optional "https" service in docker-compose.yml and compose.yaml (Compose profile "https", so it stays off
    unless asked for): Caddy built from https/ (Dockerfile + Caddyfile, so Portainer Git stacks need nothing on
    the host). HTTPS_HOST is the devices' address (an IP works); by default Caddy makes its own certificate
    authority, which each device installs once from http://<host>:8485/goodstock-root.crt; with HTTPS_CERT set to
    an email address and a public domain it gets a Let's Encrypt certificate. HTTPS on port 8443, live events
    passed straight through. README → HTTPS has the steps per device; tools/check-https.sh tests it in Docker and
    runs on GitHub. Plain http on 8484 stays, for the phone apps (they don't trust a home-made certificate).
    STILL FOR YOU: install the certificate on the kitchen tablet and check voice and notifications in Chrome 81.

[x] DONE 0.18 Automatic backups on the server. (v3.2.8)
    Before the first save of each day the server copies the kitchen to /data/backups/state-YYYY-MM-DD.json. Before
    a save that removes more than half of the inventory and recipes (from at least six) it also makes a safety
    copy, "…-before-HHMM.json", so a mistaken Wipe or a bad sync during the day loses nothing. The newest 14 are
    kept. Settings → Your data lists them (date, counts, "before a big change") with Restore, which asks first and
    then works like restoring a backup file.

[x] DONE 0.19 Restart the container when it is unhealthy. (v3.2.9)
    An "autoheal" service (willfarrell/autoheal 1.2.0) in both Compose files, behind the Compose profile
    "autoheal" instead of commented out: off by default, and in Portainer switched on with one environment
    variable. It watches only containers labelled autoheal-goodstock (the Goodstock service has that label) every
    30 seconds. Tried in Docker: a container that turned unhealthy was restarted within seconds.
