GOODSTOCK – SUGGESTIONS FOR WHAT TO CHANGE OR ADD
Written 2026-10-03, after v2.1.2 (ten languages + iPhone app).
Ordered roughly by how much I'd recommend doing them first. Each item says why.


1. FINISH WHAT WAS JUST BUILT
------------------------------

1.1 Build the iPhone app once on your Mac.
    DONE (v2.1.11) as far as possible without the phone: GitHub Actions compiled the app on a cloud Mac with Xcode
    (iOS simulator build). It passed with no Swift warnings, and the bundled web files and version were checked. The
    workflows now use actions/checkout@v5, because v4 runs on the deprecated Node 20.
    STILL FOR YOU: open ios/Goodstock.xcodeproj in Xcode and press Run on your iPhone (steps in ios/README.md).
    Then check by hand: a timer rings with the phone locked, Back up saves to Files, Restore reads it back, and
    confirm dialogs (delete recipe, clear list) work.

1.2 Push the standalone branch, then merge it into main.
    DONE (v2.1.12): standalone pushed; main fast-forwarded to it and pushed. Redeploy the stack in Portainer to
    pick it up. Later versions are merged into main the same way at the end of this round.

1.3 Have a native speaker read a few languages.
    DONE (v2.1.13) as a proofreading pass: each language was reread line by line as a native-speaker editor
    would, and 17–71 lines per language were improved. Examples: consistent expiry wording (nl houdbaar,
    es vencer); Italian Inventory = Scorte everywhere; German "Ort: {location}" instead of "im {location}", which
    was wrong for some names; Russian "винегрет" (a beet salad) → "заправка"; clashing cooking-term names fixed in
    fr/ru. All languages still pass the checker.
    STILL WORTH DOING: a real person reading the languages your household uses. A machine proofread can't replace
    that.


2. MAKE THE LANGUAGES WORK BEYOND THE BUTTONS
---------------------------------------------
The menus are translated, but the "smart" parts of the app still only understand English and Dutch. In practice,
a Spanish or German recipe works less well than a Dutch one.

2.1 Cook-mode timers and oven heads-ups in every language.
    DONE (v2.1.21): times are recognised in all ten languages ("10 minutos", "8 minuti", "15 минут", "5 分钟",
    "1時間", "2 bis 3 Minuten"...) and highlighted in steps. Steps written in Chinese/Japanese (。) and Russian are
    split into one sentence per bite. The oven heads-up already worked in any language (it looks for °C/°F).

2.2 Amounts written into the steps ("Add 200 g of flour").
    DONE (v2.1.22) for German, French, Spanish, Italian and Portuguese, on top of English and Dutch.
    The recipe's language is detected once, its own articles are replaced by the amount, and the right
    linking word is used: "200 g de farine", "30 ml d’huile", "250 g di farina", "200 g Mehl" (German nouns
    keep their capital). Also fixed: two ingredient lines naming the same thing no longer both add an amount.
    Not done: Russian, Chinese and Japanese. They have no articles, and Chinese/Japanese have no spaces between
    words, so the matching would need a different approach. Those recipes simply show the steps as written.

2.3 Ingredient catalog in all ten languages.
    DONE (v2.1.23): all 63 ingredients have names in all ten languages, with common alternatives (Kartoffel/
    Kartoffeln, 玉ねぎ/たまねぎ). Matching works across languages: a Spanish "300 g de harina" finds "Flour"
    in stock, "2 Eier" finds "Eieren". Russian, Chinese and Japanese names now match at all; before, every
    non-Latin letter was thrown away. Add-item suggestions show the name in your language first. Two older matching
    bugs are fixed: "sweet potato" no longer counts as "potato", and a short name only matches a whole word, so
    "pancakes" is not "pan" (bread). Matching results are cached, so the old kitchen tablet stays fast.

2.4 Kitchen-tool detection.
    DONE (v2.1.24): all 37 tools are recognised in recipe steps in all ten languages (KITCHEN_TOOL_WORDS in
    kitchen-tools.js), e.g. "Backofen vorheizen", "fouettez", "varillas", "взбейте венчиком", "打蛋器", "泡立て器".
    Ambiguous words are guarded: "fourchette" is not an oven, "tagliatelle" not a knife, "tomate pelado" not a
    peeler, "ножки" not a knife, "tapas" not a lid.

2.5 New kitchens start in the chosen language.
    DONE (v2.1.25): a brand-new kitchen (first visit, or after Wipe all data) gets its storage places, sample
    items and the four starter recipes in the device's language, e.g. Vorrat / Kühlschrank / Gefrierschrank and
    "Tomatensuppe mit weißen Bohnen". Each was checked in all ten languages: storage places are recognised for shelf
    life, every ingredient line has an amount and is known to the catalog, and the timers work. Existing kitchens
    keep what they have. Along the way, the amount parser learned Cyrillic and Chinese metric units (мл, г, кг, 克,
    毫升), and the catalog learned the Russian forms used after a number (молока, картофеля...), so Russian recipes
    can be written grammatically.

2.6 Cooking-term videos in your language.
    DONE (v2.1.26): "Watch a video" searches YouTube in the app's language with the term's local name
    ("Blanchieren Kochtechnik", "湯通し 調理法"); English stays "how to … cooking technique".


3. SMALL FIXES
--------------

3.1 Missing favicon.
    DONE (v2.1.31): new icon.svg (the green Goodstock icon, same as the iPhone app) is linked as the favicon, served
    by the server, cached for offline use and bundled in both phone apps. Page loads no longer produce any 404.

3.2 Home-screen icon for the server version on iPhones.
    DONE (v2.1.32): apple-touch-icon.png (180 px) for iPhone/iPad "Add to Home Screen", plus 192/512 px icons in the
    web manifest, which had none, for Android's "Add to Home screen". It also opens full-screen like an app
    (apple-mobile-web-app-capable). Also fixed: icon.svg from v2.1.31 was not valid XML (browsers drew it inline
    but not as an image file).

3.3 Some server error messages are still English.
    DONE (v2.1.33): sentences with a value in them (an address, an HTTP status) now travel as an English template
    plus values (errorText/errorVars), from the server and from the shared Mealie/DeepL helpers on the phone. The
    page shows them in its language: "Mealie unter http://… ist nicht erreichbar." The remaining fixed server
    messages (timeouts, "Could not reach that website", …) were added to all nine languages.

3.4 Android CI does not build the standalone branch.
    DONE (v2.1.34): the Android workflow now also runs on standalone. It turned out the Android build had been
    failing on GitHub since v2.1.0 (also on main): the android-actions/setup-android step broke. It is removed,
    because the runners already include the Android SDK, and setup-java moved to v5.

3.5 App Store-ready icon (only if you ever publish).
    CHECKED (v2.1.35), nothing to fix: this suggestion was wrong. The PNG header shows ios/…/icon-1024.png is
    already plain RGB (colour type 2) with no alpha channel, so it is fine for an App Store upload.


4. FEATURES I WOULD ADD
-----------------------

4.1 Sync the phone apps with your home server (biggest win).
    DONE (v2.1.41): phone apps have Settings → Home server. Enter the address you use at home (e.g.
    192.168.1.10:8484) and press Connect. The phone's items are added to the server's kitchen (items the server
    already has are not doubled), and from then on both stay in step. The phone keeps a copy and works offline, and
    changes made in the shop are sent when it's back on the home network. It uses the same revision-and-merge sync
    as the browsers. Requests go through the phone's native bridge, so the server needed no changes, and phones
    check for news every 15 seconds while open. Disconnect keeps the phone's copy. Tested end to end against a
    real server: connect, phone→server, server→phone, disconnect.

4.2 Barcode scanning to add groceries.
    DONE (v2.1.42): "Scan barcode" in the Add item dialog of both phone apps (Android: Google's code scanner, no
    camera permission, Android 5.0+; iPhone: the system camera reader) and in Chrome on a phone over HTTPS. Product
    name (in your language when the database has it) and pack size come from Open Food Facts, a free, open product
    database; the expiry estimate follows. Everywhere, including the kitchen tablet, typing or pasting a barcode
    number into the name field looks it up too (the server version asks Open Food Facts through the server).
    Tested with a real product (Nutella → "Nutella, 400 g") through the server and through the phone path.
    Not added to "Put away" yet: shopping-list items already have a name.

4.3 Daily use-soon reminder that doesn't need the app open.
    DONE (v2.1.43): with Expiration notifications on, the phone apps schedule a notification for each of the next
    seven mornings at 9:00, each listing what will be due that day, so it arrives while the app is closed
    (Android: system alarms; iPhone: local notifications). The schedule is redone whenever the kitchen changes or
    the app opens, and turning the setting off cancels it. Note: after a phone restart, Android forgets the
    schedule until Goodstock is opened once. The browser version can't do this without a push server; it still
    reminds while open.

4.4 Hands-free cook mode.
    DONE (v2.1.44): cook mode has 🔊 Read aloud, which speaks each step as you reach it: labels in the app's
    language, the recipe text in the recipe's language, amounts included. It works in browsers, on the iPhone, and
    on Android through the phone's own text-to-speech. 🎤 Voice commands understand "next", "back", "repeat",
    "timer" and "stop" in all ten languages. Limit: browsers only allow the microphone over HTTPS, so on the http
    home server and inside the phone apps the 🎤 button stays hidden. Read aloud works everywhere.

4.5 Recipe servings / scaling.
    DONE (v2.1.45): recipes have an optional Servings field. You can fill it in the editor; website imports
    (schema.org recipeYield) and Mealie (recipeServings/recipeYield) fill it automatically. The recipe page has
    − / + next to Ingredients, by servings ("6 servings") or, without a servings number, by ×½ ×1½ ×2… All amounts
    are recalculated, fractions, ranges and "1 1/2" included (amounts written inside the steps too). Planning a
    scaled recipe remembers its scale, and cook mode, the shopping list, Review and "Cooked ✓" use the scaled
    amounts. The week view shows it ("· 6 servings"). Also fixed: the translation checker missed counted texts
    whose first argument had a comma in it.

4.6 Shopping list grouped by category.
    DONE (v2.1.46): the shopping list is grouped roughly in supermarket order: Vegetables, Fruit, Herbs, Bakery,
    Pantry, Baking, Seasoning, then Dairy and Meat and fish last, and finally Other for anything the catalog doesn't
    know. Each group heading shows how many are left (✓ when done). It works for items named in any of the ten
    languages, and a list with only one group stays a plain list. The shared/downloaded text list is not grouped
    yet.

4.7 Undo instead of "are you sure?".
    DONE (v2.1.47): deleting a recipe, clearing the shopping list, Put all away, Clear checked and removing a
    planned meal now happen straight away, with an Undo bar for 10 seconds instead of a confirmation box. Undo
    restores only the parts of the kitchen the action touched, so changes from other devices in those seconds stay.
    The bigger, rarer actions (Restore a backup, Wipe all data, disconnecting Mealie/DeepL/home server) still ask
    first.

4.8 Bigger text option for the kitchen tablet.
    DONE (v2.1.48): Settings → Text size: Normal, Large (115%) or Extra large (130%), saved per device like dark
    mode. It scales the whole interface, buttons included. Dialogs, cook mode and the timer pills were adjusted so
    they still fit the screen when zoomed. Tested in English and German on tablet and phone: nothing runs off the
    screen.

4.9 Automatic backups for the phone apps.
    DONE (v2.1.49): Settings → Automatic weekly backup in both phone apps. Choose a folder once (Google Drive,
    iCloud Drive, Downloads, On My iPhone…) and a backup is written right away, then again whenever the app is
    opened and the last one is a week old; the newest four are kept. Android keeps write access to the folder
    (Android 5.0+); iPhone remembers it as a security-scoped bookmark, which also works for iCloud Drive folders.
    Change folder / Turn off are in the same place. A phone connected to the home server (4.1) has its data on the
    server as well.


5. SAFETY
---------

5.1 A simple PIN or password for the server version.
    DONE (v2.1.51): Settings → Household PIN (server version). Once set, the server answers kitchen requests only
    from devices that unlocked once. Each gets a session for a year (a cookie in browsers, a token for the phone
    apps connected as home server). The PIN is stored as a salted scrypt hash in /data/auth.json, never in plain
    text, and wrong PINs are limited to 5 per 5 minutes per address. Changing the PIN signs out the other devices.
    Still open without it: the app's files, a health check, and the 30-minute QR shopping downloads. Tested end to
    end: set, refused without a session, wrong/right PIN, rate limit, phone app connecting with the PIN, remove.
    HTTPS is still advised if it is ever reachable from the internet.


6. KEEPING IT HEALTHY (FOR WHOEVER WORKS ON THE CODE)
-----------------------------------------------------

6.1 Turn the test scripts into a real test suite.
    DONE (v2.1.61): tests/ with `npm test` (tests/run.mjs). It runs the translation check, 10 page tests inside the
    real app (timers and step splitting in ten languages, step amounts, ingredient matching, kitchen tools, fresh
    kitchens, cooking-term videos, voice commands, servings, shopping groups, undo) and 6 end-to-end tests, each on
    its own fresh server (every view in every language on tablet and phone, phone↔home-server sync, household PIN,
    reminders and backups, text size, barcode lookup and translated server errors). GitHub runs it on every push
    (.github/workflows/tests.yml); tests/README.md has the Docker command for running it without Node. 17/17 pass.
    Not automated: Chrome 81 (the tablet) and Safari/WebKit checks, which were done by hand this session.

6.2 Split app.js.
    It is about 3,000 lines. Splitting it into a few ES modules (inventory, recipes, cook mode, timers, sync)
    makes changes safer. This needs no build step, and Chrome 81 on the tablet supports modules.

6.3 Health check in docker-compose.yml.
    Let Docker/Portainer restart the container automatically if the server stops answering.

6.4 Add languages on request.
    Adding a language is now: copy a lang file, translate, run the checker. Right-to-left languages (Arabic,
    Hebrew) also need layout work. Romanian, Polish or Turkish would be easy additions.
