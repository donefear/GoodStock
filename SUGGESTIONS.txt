LOOSE ENDS FROM THE FIRST LIST AND FROM v3.0.2
----------------------------------------------

[x] DONE 0.1 Keep "Host this kitchen" running on Android when the screen is off. (v3.0.4)
    HostService, a foreground service, runs while hosting. It shows a quiet "Sharing your kitchen" notification in the
    app's language, which opens the app when tapped, and holds a wake lock and a Wi-Fi lock. If Android stops the
    app, the service restarts and resumes the host with the same PIN and kitchen. Stopping hosting in Settings ends
    the service too. There's no Stop button on the notification: stopping from there would leave the page thinking it
    still hosts. Some makers (Samsung, Xiaomi…) still close background apps; android/README says to set battery use to
    Unrestricted.
    STILL TO CHECK on a real phone: the other devices stay in step with the host's screen off for an hour.

[x] DONE 0.2 Try the two new ways of sharing (v3.0.2) on real devices. (v3.0.4, the part that can be done in code)
    Conflict copies: Syncthing, Dropbox, iCloud ("… 2.json") and Google Drive copies were already ignored, because
    their names don't match. OneDrive's "goodstock-sync-<id>-PCNAME.json" did match: it was read as a new device, and
    an old copy brought back items deleted since. Now a file is only read when the device named inside it matches
    its file name. The shared-folder test checks four kinds of conflict copy; without the fix it fails. iCloud
    placeholders (".name.icloud") were already downloaded first. When the host goes away, the others already show
    "Working offline · Home server not reachable · will try again" and keep their changes.
    STILL FOR YOU: a week of real use with your sync app, to see how long files take to arrive.

[x] DONE 0.3 Re-schedule the daily reminders after an Android restart. (v3.0.4)
    BootReceiver schedules the use-soon reminders and running timers again from the last lists the app gave, after a
    restart and after an app update, without opening Goodstock.

0.4 Run the iPhone app on a real iPhone.
    [ ] ON HOLD (2026-10-18): waiting until a Mac that can build the app is available.
    From 1.1, still open. The workflow now builds an unsigned .ipa for sideloading from Windows (v2.1.69). Check by
    hand: a timer rings with the phone locked, backup and restore through Files, barcode scanning, and the new
    shared-folder sync with iCloud Drive.

0.5 A real person reads the languages your household uses.
    [ ] ON HOLD (2026-10-18): waiting until people are found to test the languages.
    From 1.3 and 6.4. All 13 languages have only had a machine proofread. One evening with a native speaker per
    language catches what the checker can't, like the wrong tone, odd words and text that gets cut off on buttons.


EVERYDAY USE
------------

[x] DONE 0.6 Search in the inventory and in recipes. (v3.2.0)
    Correction: both pages already had a search field ("Find something", "Search recipes or ingredients"). I missed
    them because those pages are built in app/views.js, not index.html. What was missing was the catalog: search
    was plain text only. Now a search also goes through the ingredient catalog in all 13 languages, so "harina" or
    "farine" finds Flour, "Eier" or "яйц" finds Eggs, and "salsa de soja" finds a recipe with soy sauce. Catalog
    matches start at three letters (one for Chinese and Japanese).

[x] DONE 0.7 Staples: "always keep at least …". (v3.2.0)
    The item dialog has "Keep at least". Below that amount (after −, "Cooked ✓" or an edit) the item goes onto the
    shopping list once, with a "restock" tag. If you take it off the list, it isn't added again until it has been
    back above the minimum. Removing a staple also lists it, and putting it away keeps it a staple.

[x] DONE 0.8 "Opened" and "frozen on" dates. (v3.2.0)
    "Opened today" in the edit dialog shortens the date to how long the item keeps once open (milk 4 days, canned
    tomatoes 4, peanut butter 90; 13 catalog items have an "opened" value, Dairy and Meat/fish have category
    defaults, unknown items 5 days). A date that is already sooner stays. Dry goods, fruit and vegetables show no
    button. Unlike my note above, an opened item's shorter date also replaces a package date, since that date only
    holds while closed. Freezer items have a "Frozen on" date (today for new ones), and the estimate counts from it.
    The row shows "opened …" or "frozen …".

[x] DONE 0.9 Leftovers after cooking. (v3.2.0)
    The "Cooked ✓" dialog has "Put leftovers in the fridge" (not ticked by default). It adds "Leftovers: <recipe>"
    to the fridge, due in 3 days, so it shows in Use soon.

[x] DONE 0.10 Used up or thrown away? A small waste overview. (v3.2.0)
    "Remove item" asks "Why is it gone?": Used up, Thrown away, or Just remove. A "This month" card on the
    Inventory page then shows e.g. "1 used up · 2 thrown away · Thrown away: Bread ×2". The answers are kept for a
    year in the kitchen (state.log), synced like the rest. Not done yet: using them to tune the expiry estimates.

[x] DONE 0.11 Barcodes in "Put away", and scan to use up. (v3.2.1)
    "Put it away" has Scan barcode: it fills in the pack size and keeps the barcode with the item. When the catalog
    knows the product's name and not the list's ("Volle melk" for "melk"), the expiry estimate uses the product.
    The Inventory page has Scan: an item is found by its saved barcode, or else by the product's name (and the
    barcode is then remembered). It offers Use one (for items counted in pieces), Used up, Thrown away and Edit;
    an unknown product can be added from there with its barcode. The buttons show where the camera can scan: the
    phone apps, and Chrome on a phone over HTTPS (see 0.17).

[x] DONE 0.12 Group the shared and downloaded shopping list too. (v3.2.2)
    The phone apps' share text and the QR download have the same supermarket groups as the list on screen, with
    the headings (and the title) in the app's language. A list with only one group has no headings.

[x] DONE 0.13 Recipe photos. (v3.2.3)
    The recipe editor has Add a photo (camera or gallery). Imports read schema.org "image"; on the server version
    the server fetches it once (/api/photo, images only). Photos are shrunk in the page to 480 px as JPEG (about
    20–40 KB) and shown on the recipe card and page. Mealie recipes show their photo from Mealie.
    Changed from my note above: the small photo is saved inside the recipe, not next to the kitchen data. A separate
    photo store would have needed its own sync for each way of sharing (server, phone joined to a server, hosting,
    shared folder) and for backups; inside the recipe it works offline and everywhere. The cost is a larger
    kitchen file, which stays fine for a few dozen photos. Imports in the phone apps keep the photo's web address,
    since the phone bridges only fetch text.

[x] DONE 0.14 Print a recipe or the shopping list. (v3.2.4)
    Print on the recipe page and the shopping list. The @media print section at the end of styles.css leaves out
    menus and buttons, prints light even in dark mode, and adds a small "Goodstock · date" footer (with the source
    link for recipes). The recipe keeps its photo, ingredients, tools and numbered steps with amounts; the list
    keeps only what is still unchecked, in its groups, with tick boxes. Not in the phone apps: their web views
    can't print (Android would need its PrintManager through the bridge).

[x] DONE 0.15 Faster week planning. (v3.2.5)
    "Repeat last week" (shown when last week has meals that aren't planned again yet) plans them on the same
    weekdays, with their servings. "Copy this day to…" opens a row of the other days of this week and the next.
    Neither doubles a meal that is already planned on that day, and both can be undone. The recipe picker puts
    recipes that use something from Use soon first, tagged "Uses milk soon".

[x] DONE 0.16 Recipe favourites and a "last cooked" note. (v3.2.6)
    A ☆/★ on every recipe card and on the recipe page ("★ Favourite"). It's saved with the recipe, so the whole
    household shares it. The Recipes page gets a "★ Favourites" filter once there is a favourite (remembered per
    device). The recipe page says "Cooked 6 times, last 12 days ago" or "Not cooked yet", counted from meals
    marked Cooked ✓ up to today.


SERVER VERSION
--------------

0.17 Easy HTTPS (biggest win for the server version).
    Several features stay off on the plain-http home server: 🎤 voice commands, browser notifications, barcode
    scanning in phone browsers, and the offline service worker on any address other than localhost. An optional
    Caddy service in docker-compose.yml (with a local certificate, or a free certificate when you have a domain),
    plus a short README section, turns them all on at once.

0.18 Automatic backups on the server.
    The phone apps make weekly backups, but the server keeps only one /data/state.json. One bad sync or a mistaken
    "Wipe all data" and it's gone. A daily copy into /data/backups (keeping the last 14), with a "Restore from a
    server backup" list in Settings → Your data, needs no extra setup.

0.19 Restart the container when it is unhealthy.
    From 6.3. Docker only restarts a container that has stopped, not one that is unhealthy. An optional "autoheal"
    service in the Compose file (commented out by default) closes that gap.


LANGUAGES
---------

0.20 Amounts in the steps for the remaining languages.
    From 2.2 and 6.4: Russian, Chinese, Japanese, Romanian, Polish and Turkish recipes show the steps without
    amounts written in. For Chinese and Japanese, finding the ingredient's catalog name inside the sentence (there
    are no spaces) and putting the amount just before it would work for most recipes. For the other four, put the
    amount in brackets after the word ("морковь (2 шт.)"), which needs no grammar.

0.21 Right-to-left languages (only if someone asks).
    Arabic or Hebrew need dir="rtl" and CSS that flips with the text direction (margin-inline instead of
    margin-left…). This is a layout job more than a translation job. Do it only on request.


KEEPING IT HEALTHY (FOR WHOEVER WORKS ON THE CODE)
--------------------------------------------------

0.22 Test the kitchen tablet automatically.
    From 6.1: Chrome 81 is still only checked by hand. A CI job with puppeteer 2.1.1 (Chromium 80) that opens every
    view and fails on a script error would catch a stray `??=` or `.at()` before it reaches the tablet.

0.23 One command to bump the version.
    Every change bumps the label in index.html and the cache name in sw.js, by hand, and the APK reads its version
    from the label. A small `npm run bump` script that updates both (and checks they match in the tests) stops a
    forgotten cache bump from serving old files.

0.24 Split app/views.js.
    At about 87 KB it's twice the size of any other client file. It holds every page plus the recipe editor and
    translation. Moving the recipe pages, editor and translation into app/recipes.js (loaded right after views.js)
    keeps it manageable, the same way app.js was split in 6.2.

0.25 Signed desktop builds (only if others will install it).
    The portable .exe and the .dmg are unsigned, so Windows SmartScreen and macOS Gatekeeper warn people on first
    launch. That's fine for your own household. Signing, and maybe an update check, only matters if you hand the
    app to others.
